# LangChain Ecosystem — One-Line Component Reference

Here is a one-line explanation of the major components in the LangChain ecosystem, organized by category for easy reference while learning Python, LangChain, RAG, and AI agents.

## 1. Core LangChain ecosystem

| Component         | One-line explanation                                                                                      |
| ----------------- | --------------------------------------------------------------------------------------------------------- |
| LangChain         | Framework for building LLM applications by connecting models, prompts, tools, and data sources.           |
| LangChain Core    | Provides foundational abstractions such as messages, prompts, documents, and runnable interfaces.         |
| LangChain Classic | Provides legacy chains and components for applications built using older LangChain APIs.                  |
| LangGraph         | Builds stateful, multi-step AI agent workflows with conditional routing, persistence, and human approval. |
| LangSmith         | Helps trace, debug, evaluate, monitor, and improve LLM applications and agents.                           |

## 2. Models and AI providers

| Component          | One-line explanation                                                                      |
| ------------------ | ----------------------------------------------------------------------------------------- |
| Chat Models        | Accept conversational messages and generate assistant responses.                          |
| LLMs / Text Models | Accept text prompts and generate text completions.                                        |
| Model Providers    | Integrations that connect LangChain to AI services such as OpenAI, Anthropic, and Google. |
| Ollama             | Enables LangChain to communicate with locally hosted AI models.                           |
| Embeddings         | Convert text into numerical vectors that represent semantic meaning.                      |
| Multimodal Models  | Process multiple input types, such as text, images, and audio, when supported.            |
| Structured Output  | Produces model responses in a defined structure, such as JSON or a Pydantic schema.       |

## 3. Prompts and messages

| Component          | One-line explanation                                                               |
| ------------------ | ---------------------------------------------------------------------------------- |
| Prompt Templates   | Reusable instructions containing variables that are filled in before a model call. |
| ChatPromptTemplate | Creates structured system, user, and assistant messages for a chat model.          |
| System Message     | Defines the model's role, instructions, and behavioral constraints.                |
| Human Message      | Represents the user's input to the model.                                          |
| AI Message         | Represents a response generated by the model.                                      |
| Few-Shot Prompting | Provides example inputs and outputs to guide the model's responses.                |
| Output Parsers     | Convert model responses into a desired format or data structure.                   |

## 4. Documents and data loading

| Component        | One-line explanation                                                                  |
| ---------------- | ------------------------------------------------------------------------------------- |
| Document         | Stores text content along with metadata such as source, page number, or category.     |
| Document Loaders | Import information from PDFs, text files, websites, databases, and other sources.     |
| Text Splitters   | Divide large documents into smaller chunks suitable for embedding and retrieval.      |
| Metadata         | Stores descriptive information about a document or text chunk.                        |
| Blob             | Represents raw data that can be processed by document-loading and parsing components. |

## 5. Retrieval and RAG

| Component                            | One-line explanation                                                                            |
| ------------------------------------ | ----------------------------------------------------------------------------------------------- |
| RAG (Retrieval-Augmented Generation) | Retrieves relevant external information and supplies it to an LLM to generate grounded answers. |
| Retriever                            | Finds and returns documents relevant to a user's query.                                         |
| Vector Store                         | Stores vector embeddings and supports similarity searches over stored content.                  |
| Vector Database                      | Provides specialized storage and querying for vectors, often with metadata filtering.           |
| Semantic Search                      | Finds information based on meaning rather than exact keyword matches.                           |
| BM25 / Keyword Search                | Finds documents by matching important words and terms in the query.                             |
| Hybrid Search                        | Combines semantic and keyword search to improve retrieval coverage.                             |
| Contextual Compression               | Removes irrelevant information from retrieved documents before sending them to the model.       |
| Reranker                             | Reorders retrieved documents according to their relevance to the query.                         |
| Indexing                             | Prepares documents by loading, splitting, embedding, and storing them for later retrieval.      |
| Parent-Child Retrieval               | Searches smaller text chunks but can return larger sections to preserve context.                |

## 6. Chains and runnable components

\| Component | One-line explanation | |---|---| | Chain | Connects multiple operations into a workflow that performs a specific task. | | Runnable | Standard interface for executing and composing LangChain operations. | | LCEL | LangChain Expression Language uses operators such as `|` to combine runnable components. | | RunnableSequence | Executes multiple components sequentially, passing each output to the next. | | RunnableParallel | Executes multiple operations on the same input and combines their results. | | RunnablePassthrough | Passes input through unchanged so it can be reused by later steps. | | RunnableLambda | Wraps a custom Python function as a runnable component. | | Streaming | Returns partial model or workflow output as it becomes available. | | Batching | Processes multiple inputs through a component in a batch. | | Async Execution | Allows supported operations to run asynchronously for improved concurrency. |

## 7. Tools and AI agents

| Component                   | One-line explanation                                                                                    |
| --------------------------- | ------------------------------------------------------------------------------------------------------- |
| Tool                        | A callable function that allows an AI application to perform a specific operation.                      |
| `@tool` Decorator           | Converts a Python function into a tool that an agent can invoke.                                        |
| Tool Calling                | Allows a model to request a tool execution with structured arguments.                                   |
| Agent                       | Uses a model to choose actions and tools dynamically to accomplish a task.                              |
| Agent Loop                  | Repeats model decisions, tool executions, and observations until the task reaches a stopping condition. |
| Tool Result                 | Contains the output returned by an executed tool.                                                       |
| Human-in-the-Loop           | Pauses a workflow for human input, review, or approval.                                                 |
| Middleware                  | Adds logic around agent execution, such as logging, retries, or policy checks.                          |
| Memory / Conversation State | Retains relevant information across workflow steps or conversational turns.                             |
| Checkpointing               | Saves workflow state so execution can resume later.                                                     |
| Guardrails                  | Apply validation and policy checks to control inputs, actions, and outputs.                             |

## 8. LangGraph components

| Component         | One-line explanation                                                                |
| ----------------- | ----------------------------------------------------------------------------------- |
| State             | Holds the shared data and progress of a graph workflow.                             |
| Node              | Executes one operation, such as calling an LLM, running a tool, or validating data. |
| Edge              | Defines the connection and execution path between graph nodes.                      |
| Conditional Edge  | Chooses the next node based on the current state or a routing decision.             |
| START             | Marks the entry point of a LangGraph workflow.                                      |
| END               | Marks the completion of a LangGraph workflow.                                       |
| Persistence       | Stores workflow state across execution steps or sessions.                           |
| Interrupt         | Pauses graph execution so a person can provide input or approval.                   |
| Subgraph          | Embeds one graph workflow inside another graph.                                     |
| Durable Execution | Supports recovery and continuation of long-running workflows using saved state.     |

## 9. Evaluation, monitoring, and testing

| Component          | One-line explanation                                                                  |
| ------------------ | ------------------------------------------------------------------------------------- |
| LangSmith Tracing  | Records model calls, tool calls, inputs, outputs, and execution timing for debugging. |
| Dataset            | Stores representative test cases used to evaluate an AI application.                  |
| Evaluator          | Scores model outputs against defined quality criteria.                                |
| LLM-as-a-Judge     | Uses an LLM to evaluate another model's response against a rubric.                    |
| Regression Testing | Checks whether code or prompt changes have broken previously working behavior.        |
| Observability      | Provides visibility into latency, errors, token usage, and workflow execution.        |
| Prompt Versioning  | Tracks prompt changes to compare results and reproduce behavior.                      |
| Feedback           | Collects user or reviewer ratings to identify and improve application weaknesses.     |

## 10. Application development and deployment

| Component             | One-line explanation                                                                                                         |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| FastAPI               | Exposes Python AI applications through HTTP APIs and endpoints.                                                              |
| Streamlit             | Builds interactive web interfaces for Python-based AI applications.                                                          |
| Environment Variables | Store configuration and secrets outside source code; sensitive `.env` files should be excluded from public Git repositories. |
| Caching               | Reuses eligible previous results to reduce repeated processing and latency.                                                  |
| Retries               | Reattempts failed operations according to a configured policy.                                                               |
| Rate Limiting         | Restricts request frequency to protect services and manage provider limits.                                                  |
| Token Usage           | Measures input and output tokens, which influence model cost and context capacity.                                           |
| Deployment            | Publishes an AI application to a local environment, server, container, or cloud platform.                                    |
